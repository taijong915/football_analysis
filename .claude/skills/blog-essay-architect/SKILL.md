# Skill: Data-Driven Essay & Column Architect

## 1. Overview & Objective
본 스킬은 데이터 분석 결과와 통계 보고서를 일반 독자와 전문가 모두가 몰입할 수 있는 **'스토리텔링형 인사이트 칼럼(에세이)'**으로 재구성하는 프레임워크를 정의합니다.
기술적 나열이나 연구 보고서식 순서를 지양하고, **독자의 호기심 유발 → 핵심 발견 → 반전과 심화 → 한계** 순서로 전개하여 글의 몰입도와 가독성을 극대화합니다.

---

## 2. Core Philosophy (핵심 원칙)
- **Insight, Not Plumbing**: 독자가 궁금한 것은 '무엇을 알아냈나'이지 '어떻게 알아냈나'가 아닙니다. 방법론은 결과를 읽는 데 꼭 필요한 만큼(무엇을 셌는지 한두 문장)만 씁니다.
- **Results, Not Process**: 분석 과정에서 부딪힌 어려움과 그 극복 과정 - 원천 데이터의 문제, 조작적 정의의 수정, 보정 방법, 처음 분석 대비 수치·순위의 변화 - 은 블로그에 쓰지 않습니다. 이런 내용은 프로젝트 내부 기록(`DECISIONS.md`, `PLAN.md`, `RESULTS.md`)에만 남깁니다. 블로그의 수치는 최종 결과 하나만 제시합니다.
- **Cognitive Cost Management**: 독자가 글에 흥미를 느끼기 전에 높은 인지 비용(좌표계, 복잡한 통계 기법 등)을 치르게 하지 않습니다.
- **No Redundant Summaries**: 서두의 요약 불릿, 본문, 말미의 결론 불릿으로 이어지는 3단 복제 구조를 금지합니다. 반전과 전개 과정을 통해 자연스럽게 읽히도록 설계합니다.
- **Domain Intuition Over Plain Numbers**: 단순 수치 나열에 그치지 않고, 도메인 상식(규칙, 현업 감각)으로 그 숫자가 경기에서 무엇을 뜻하는지 해석해 줍니다.

## 2.5. 적용 전 적합성 검토 (원고 작성 전 필수)

이 스킬의 5단계 구조는 `korea_qatar2022`(여러 팀 비교 + 한 팀 조명)를 바탕으로 만들어져, 형태가 다른 주제에는 맞지 않을 수 있습니다. 원고를 쓰기 전에 주제의 `RESULTS.md`에서 핵심 발견을 뽑아 5단계에 배치해 보고, 맞지 않으면 억지로 채우지 말고 스킬부터 고칩니다. 이 검토는 사용자와 스킬 수정 여부를 정해야 할 수 있으므로 메인 세션이 합니다.

**배치표** - `blog/<주제>/ARC_MAP.md`에 저장합니다.

| 단계 | 넣을 발견 | 근거 (`RESULTS.md` 위치) |
| :--- | :--- | :--- |
| Step 1 Hook | | |
| Step 2 핵심 발견 | | |
| Step 3 반전 | | |
| Step 4 심화 | | |
| Step 5 한계 | | |
| **자리 없는 발견** | | |

**판정**
- **적합**: 핵심 발견이 모두 자리를 찾고, 비는 단계가 1개 이하입니다. 배치표를 원고 설계도로 삼아 작성합니다(`blog-draft` 에이전트에 넘깁니다).
- **부적합 신호** - 하나라도 해당하면 원고 작성 전에 스킬 수정을 사용자와 논의합니다.
  - Step 1·3·4 중 2개 이상이 빈다.
  - "자리 없는 발견"에 중요한 결론이 들어간다(예: 원인 검증, 예외 사례, "차이 없음" 결과).
  - 어떤 단계를 채우려면 `RESULTS.md`에 없는 통념이나 대비를 만들어내야 한다.
- 이미 알려진 일반화 문제 목록은 `DECISIONS.md` 2026-09-16 "블로그 글쓰기 스킬 적합성 검토 단계 도입" 항목에 있습니다. 부적합 신호가 나오면 그 목록에서 출발합니다.

## 3. Universal Narrative Arc (5단계 구조 및 작성 예시)

글의 주제나 도메인이 바뀌어도 다음의 5단계 흐름을 일관되게 적용합니다. 주제에 해당 요소가 없는 단계(예: 2차원 분류 축이 없는 주제)는 억지로 만들지 말고 건너뜁니다.

> 아래 적용 예시는 `korea_qatar2022` 분석에서 가져온 문장으로, 문장의 톤과 구조를 보여주는 용도입니다. 수치나 세부 설명의 출처가 아니므로, 같은 주제로 원고를 쓸 때는 예시 문장을 옮기지 말고 `RESULTS.md`와 다시 대조하세요.

### Step 1. Hook (직관과 질문)
- **역할**: 독자의 호기심 유발 및 글의 문제의식 정의
- **내용**: 일상적 상식, 업계의 정설, 현장의 직관적 외침을 화두로 던지고 "이게 진짜 사실일까?"라는 질문으로 시작합니다.
> **적용 예시**
> "2026 북중미 월드컵에서 대표팀이 고전할 때마다 해설진은 목청을 높여 외쳤습니다. '앞 선수가 뛰어 들어가 줘야 합니다!' 이 대회 데이터는 아직 공개되지 않았지만, 4년 전 카타르 월드컵 자료로는 그 말을 재 볼 수 있습니다. 과연 해설의 이 한마디는 대회에서 오래 살아남는 팀의 조건이었을까요?"

### Step 2. Core Finding (핵심 발견과 반직관적 대비)
- **역할**: 질문에 대한 1차 검증 및 지적 쾌감 제공
- **내용**: 질문에 대한 명확한 데이터적 결론을 먼저 제시합니다. 결과 안에 겉보기 조건은 같지만 방향이 반대로 갈리는 **대비 요소(A vs B)**가 있으면 시각 자료와 함께 부각합니다. 대비는 `RESULTS.md`에 근거가 있을 때만 쓰고, 없으면 결론을 그림과 함께 담백하게 보여준 뒤 Step 3으로 넘어갑니다.
> **적용 예시**
> "결론부터 말하면, 사이드와 하프스페이스로 파고들 준비가 된 선수가 많은 팀일수록 16강에 더 많이 올랐습니다. 두 값이 함께 움직이는 정도를 -1에서 +1 사이로 재면(0이면 무관) +0.34로, 강하지는 않아도 분명한 방향입니다. 그런데 박스 중앙에서 컷백을 기다린 선수를 같은 조건으로 세자, 방향이 오히려 반대로 기울었습니다(-0.13). 침투의 성패를 가른 것은 '몇 명이 섰느냐'가 아니라 '어디에 섰느냐'였습니다."

### Step 3. The Twist (핵심 주체 조명과 통념 뒤집기)
- **역할**: 글의 클라이맥스, 가장 흥미진진한 반전
- **내용**: 독자가 가장 관심 있는 핵심 주체(예: 대한민국 대표팀)를 최종 결과로 조명하고, 통념·해설의 인상과 실제 결과가 어긋나는 지점에서 반전을 줍니다. 반전은 **통념 vs 최종 결과** 사이에서 만들고, **분석 전후 수치 변화**(보정 전/후, 처음 정의 vs 바뀐 정의)로 만들지 않습니다. 결과에 통념과 어긋나는 지점이 없으면 반전을 억지로 만들지 말고 대상의 위치를 담백하게 보여줍니다.
> **적용 예시**
> "그렇다면 해설이 답답해했던 한국은 어땠을까요? '앞에 아무도 없었다'는 인상과 달리, 2022년 한국의 채널에 파고들 준비가 된 선수 수는 32팀 중 15위로 딱 한가운데였습니다. 컷백을 기다리는 중앙 인원은 오히려 25위로 평균보다 많은 편이었습니다. 적어도 4년 전의 한국은 앞에 뛰어들 선수가 모자란 팀이 아니었습니다."

### Step 4. Typology Framework (심화: 2차원 분류)
- **역할**: 지표의 입체화 및 단편적 해석 방지
- **내용**: 지표에 영향을 미치는 외부 변수(예: 볼륨, 환경적 제약)를 다른 축으로 두어 **2차원 매트릭스(2x2 등)**로 세분화하고, 숫자는 같지만 성격이 정반대인 극단적 사례를 비교합니다.
> **적용 예시**
> "침투 수치가 낮다고 해서 모두 답답한 팀은 아니었습니다. 가로축에 '전진한 횟수', 세로축에 '한 번 전진할 때 파고들 준비가 된 인원'을 놓자 성격이 정반대인 두 유형이 갈렸습니다. 4강 돌풍의 모로코는 밀어붙일 일 자체가 적어 전진 횟수가 중간 팀의 3분의 2에 그쳤고(모로코형), 8강에서 멈춘 포르투갈은 중간 팀의 1.5배나 밀어붙이고도 파고들 자리를 만들지 못했습니다(포르투갈형)."

### Step 5. Pragmatic Limitations (한계와 결론)
- **역할**: 분석적 정직함 유지 및 여운을 주는 마무리
- **위치와 분량**: 한계는 **글 마지막에만, 짧게** 씁니다. 본문(Step 1-4) 중간에 "다만 이 수치는 ~한 한계가 있어" 같은 단서를 끼워 넣지 않고, 이 단계에 모아 핵심 한계 2-3개를 몇 문장으로 정리합니다.
- **내용**: 표본·측정의 한계, 상관관계와 인과관계의 차이를 솔직히 짚고(한계가 무엇인지만 쓰고, 그 한계를 분석 중에 어떻게 발견하고 다뤘는지는 쓰지 않습니다), 기계적인 요약 꼬리표 없이 독자에게 생각할 거리를 던지며 담백하게 닫습니다.
> **적용 예시**
> "채널 침투가 16강 진출과 함께 움직였다고 해서 '파고들기만 하면 올라간다'는 뜻은 아닙니다. 강팀이라 공을 오래 쥐었고, 공을 쥐어서 채널이 열린 것일 수도 있으니까요. 다만 한 가지는 분명합니다. 축구든 데이터든, 전체 화면을 넓게 보지 않고 숫자를 평면적으로 읽는 순간 우리는 엉뚱한 결론에 도달하게 됩니다."

## 4. Writing & Formatting Rules

### Paragraph & Scaffolding
- **문단 호흡**: 한 문단은 3~4문장을 넘기지 않으며, 모바일 가독성을 위해 문단 간 빈 줄을 확실히 둡니다.
- **강조 표기**: 핵심 발견, 반전 수치, 대비되는 개념은 **인라인 볼드**로 시각적 스캔이 가능하게 처리합니다. 단, 볼드는 **한 문단에 1개 이내**로 씁니다. 볼드가 많으면 무엇이 핵심인지 흐려지고, 윤문 단계(`humanize-korean`)에서 AI 티 패턴으로 잡혀 깎입니다.
- **용어**: 통계 용어는 일반 독자 기준으로 풀어 씁니다("상관관계" -> "함께 움직이는 정도", "분산" -> "수치가 벌어지는 정도", "통제하면" -> "감안하면"). 축구 팬이 흔히 아는 용어(하프스페이스, 컷백, 오픈플레이 등)는 풀지 않습니다. 분석에서 만든 지표 이름("침투 밀도" 등)과 데이터 수집 용어("가시율" 등)는 축구 팬 상식이 아니므로 뜻으로 풉니다.
- **수치 제시**: 단순 통계 나열보다 상대적 비교 표현("대회 평균의 2.2배", "3분의 1 수준")을 함께 써서 직관성을 높입니다.

### Modifiers (수식어)
- **수식어의 강도는 수치가 받쳐주는 만큼만**: "압도적", "정확히", "완전히" 같은 크기 수식어에는 비교 수치를 함께 쓰고, 근거가 약하면 수치로 바꿉니다("압도적으로 쥐고도" -> "대회 중간 팀의 1.5배나 밀어붙이고도").
- **상관 결과에 인과 동사를 쓰지 않습니다**: "견인했다", "이끌었다", "만들어냈다" 대신 "~일수록 많았다", "함께 움직였다"를 씁니다.
- **흥미는 형용사가 아니라 대비와 반전에서 만듭니다**: "그런데", "하필", "반대로"처럼 흐름을 표시하는 말은 자유롭게 씁니다.

### Data Visualization Anchoring
- 모든 시각 자료(차트, 표, 스냅샷)는 독자가 해당 맥락의 텍스트를 읽고 "왜 그런가?"를 품었을 때 바로 아래 배치합니다.
- 캡션에는 단순히 'A 데이터'라고 쓰지 않고, 해당 그림에서 **독자가 눈여겨봐야 할 관전 포인트(빨간 점, 역전 현상 등)**를 1~2문장으로 안내합니다.

## 5. Anti-Patterns (지양해야 할 패턴)
1. **서두 스포일러 블록**: 서두에 글 전체 내용을 5~6줄로 요약한 불릿 리스트를 넣지 않습니다.
2. **학술 논문식 시계열 구성**: [데이터 소개 → 전처리/보정 → 가설 검증 → 결과] 순으로 쓰지 않습니다. (철저히 '독자의 지적 호기심 흐름'을 우선)
3. **분석 과정 서술**: 데이터 클렌징 고충, 수식 유도, 원천 데이터의 문제와 그 보정 방법, 조작적 정의를 바꾼 이력, 처음 분석 대비 수치·순위가 어떻게 달라졌는지를 본문에 넣지 않습니다. 독자는 분석가가 어떤 어려움을 어떻게 극복했는지 궁금해하지 않습니다. 이런 내용은 `DECISIONS.md`·`PLAN.md`·`RESULTS.md`에만 기록합니다.

- **엠대시·엔대시 금지, 하이픈("-")만** 씁니다.
- **그림**: 주제 폴더 `processed/`의 PNG를 상대경로로 참조만 하고(옮기거나 복제하지 않음), `![alt](경로)` 바로 다음 줄에 `그림 N.`으로 시작하는 캡션을 답니다. 캡션 내용은 4절의 관전 포인트 규칙을 따릅니다.
- **HTML 변환용 마커**(KICKER, STAT-STRIP, 표 강조 행, 섹션 번호)는 `blog-draft.md` 형식대로 넣습니다. STAT-STRIP은 서두 요약이 아니라 Hook 직후 호기심을 거는 수치 4개로 고르고, 결론을 다 드러내는 수치 나열이 되면 넣지 않습니다.
- **요약 섹션을 두지 않습니다**: `결론부터`·`종합하면` 같은 섹션은 2절의 No Redundant Summaries에 어긋납니다. 번호 없는 섹션은 마지막 `## 한계` 하나입니다.
- **제목은 확정하지 않습니다**: 후보 2-3개를 제안하고 원고 제목에 `[제목안]`을 표시합니다.
- **원고 이후 흐름**: 사실 대조 -> 제목·프레이밍 확정 -> `humanize-korean` 윤문 -> `blog-html` 변환 -> 태그 선정 -> 발행. 자세한 기준은 `.claude/rules/analysis-workflow.md`의 "블로그 발행 전 검토" 절에 있습니다.
